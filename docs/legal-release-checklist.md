# Исправления Velocity Club и условия выпуска

Дата: 5 октября 2026 года. Изменения подготовлены в проекте; это не подтверждение изменения публичного сайта или фактического выполнения требований бизнеса.

## Что изменено

- Переписаны политика обработки данных, оферта, пользовательское соглашение, доставка и возврат. Сохранён обещанный покупателю срок возврата 14 дней. Убраны автоматический запрет возврата обычного товара «под заказ», обязательность транспортной упаковки и неопределённый срок возврата денег после проверки.
- Регистрация принимает пользовательское соглашение отдельным действием. Обязательные данные аккаунта и заказа обрабатываются на договорном основании; рекламной подписки при регистрации нет.
- Добавлены самостоятельные тексты согласий для персонализации, обработки почты для рассылки, рекламы и аналитики. API проверяет версию и сохраняет текст, дату, источник и связь с субъектом. Старые даты регистрации / подписки не превращаются в доказательства согласия.
- Аналитика выключена до подтверждения согласия сервером. Отказ останавливает сбор, удаляет идентификатор браузера и события соответствующего подтверждения, отзывает запись согласия. Счётчик Vercel и его зависимость удалены. Настройки доступны из подвала.
- Подписка требует две пустые по умолчанию галочки. Отказ доступен по персональной ссылке, без входа в аккаунт. GET страницы не отменяет подписку: отказ подтверждается кнопкой. Выгрузки для рассылки исключают старые, отозванные и просроченные согласия; CSV содержит индивидуальную ссылку отказа.
- Профиль позволяет отозвать добровольное согласие и удалить дату рождения, пилота и команду, сохранив аккаунт.
- Для физического товара добавлены состав, изготовитель и адрес, страна, уход, документ соответствия со ссылкой в реестр, проверка маркировки и основание прав на дизайн / фото. Эти поля и внутренний чеклист помогают заполнить реальные сведения; отсутствие новых полей не скрывает товары и не блокирует их публикацию или добавление в корзину.
- До подтверждения заказа показывается конечная календарная дата передачи. Она, редакция оферты, правила возврата и характеристики товара сохраняются с заказом. В кабинете и на странице результата доступно скачивание подтверждения. Старым заказам новая редакция автоматически не приписывается.
- В контакты и подвал добавлены известные реквизиты продавца. Адреса и регистрирующий орган берутся из конфигурации и не выдумываются.
- Исправлены права на возврат оплаченной суммы сертификата, в том числе остатка после активации; добавлен путь обращения за денежным возвратом. Автоматическое перечисление денег по требованию не выполняется.
- Переведены видимые служебные английские подписи. Убраны ссылки продвижения Instagram. По указанию владельца все действующие товары, исходное фото и GIF на главной сохранены. Права на эти и остальные материалы остаются отдельным пунктом проверки.
- Добавлены страница `/admin/compliance`, проверка готовности и обработка сроков хранения. Есть отметка спора в заказе, защищающая его от планового удаления.

## Обязательно получить от владельца

| Требование | Что требуется | Статус |
|---|---|---|
| Реквизиты | Действительный адрес ИП и наименование регистрирующего органа | Неизвестно |
| Возврат | Фактический адрес, индекс и получатель, способ приёма посылок | Неизвестно |
| Одежда | Документы поставщика: состав, изготовитель / адрес, страна, уход, применимость ТР ТС 017/2011, действующие сертификаты / декларации и их записи в реестре | Неизвестно |
| Маркировка | Классификация товаров, обязанность маркировки, регистрация / коды / проверка и вывод из оборота в «Честном знаке» | Неизвестно |
| Права | Разрешения на знаки команд / чемпионата, изображения пилотов, фото и принты, либо подтверждение собственного дизайна без чужих объектов | Неизвестно |
| Размещение данных | Реальный регион приложения, базы, реплик, резервных копий, журналов, Redis и иных обработчиков | Неизвестно |
| Роскомнадзор | Поданное уведомление оператора с актуальными целями, адресами баз и обработчиками; проверка трансграничных передач и отдельных уведомлений при их наличии | Неизвестно |
| Касса | Подключённая ККТ / ОФД, налоговые настройки, чеки на оплату, зачёт предоплаты, сертификаты, смешанную оплату и возврат, маркировка | Неизвестно |
| Срок | Реальные предельные календарные сроки производства и доставки для каждого включённого направления | Неизвестно |

Товары с неизвестными сведениями нельзя заполнять предположениями. «Фанатский мерч», изготовление после заказа и отсутствие претензий правообладателя не заменяют проверки прав и требований к товару.

## Настройки и миграции

1. Развернуть приложение и PostgreSQL на подтверждённой российской инфраструктуре. Российский домен провайдера не доказывает физическое размещение. Ранее предложенный Neon не использовать для первичного сбора данных российских покупателей без соответствующего законного основания и проверки архитектуры. Также проверить журналы запросов и сторонний Redis, получающий IP-адреса.
2. Перед обновлением схемы сделать резервную копию. Для существующей базы использовать `npm run db:migrate:deploy`, затем `npm run db:generate`; запуск Next сам по себе не обновляет таблицы. 05.10.2026 после ошибки входа четыре миграции `20261005…` применены к базе из текущего `.env`, после создания и проверки резервной копии. Количество аккаунтов, товаров, заказов и подписчиков не изменилось. Для другого окружения проверить миграции отдельно.
3. Заполнить реальные `NEXT_PUBLIC_SELLER_ADDRESS`, `NEXT_PUBLIC_SELLER_REGISTRATION_AUTHORITY`, `NEXT_PUBLIC_RETURN_ADDRESS`, `NEXT_PUBLIC_RETURN_RECIPIENT`.
4. Заполнить `NEXT_PUBLIC_PRODUCTION_MAX_CALENDAR_DAYS` и `NEXT_PUBLIC_DELIVERY_MAX_CALENDAR_DAYS`: целые числа 1–365. Они включают выходные и праздники, срок отсчитывается от подтверждения заказа, а не от поступления оплаты. Это обязательство продавца. До задания сроков онлайн-покупка физического товара недоступна.
5. При изменении реквизитов / юридического текста изменить `LEGAL_VERSION`. Пересобрать сайт после изменения любых публичных настроек: они входят в клиентский пакет. Все клиентские формы должны отправлять новую версию; сохранённые документы прежних заказов не перезаписывать.
6. Только после документированной проверки включить `PERSONAL_DATA_RF_VERIFIED`, `RKN_NOTIFICATION_VERIFIED`, `RETENTION_JOB_VERIFIED` и `FISCAL_PROCESS_VERIFIED`. Эти флаги — подтверждение владельца, а не результат автоматической проверки. С ними не подаются заявления и не подключается касса. При незаполненных подтверждениях production блокирует новую регистрацию, подписку, аналитическое согласие и оплату; отказ от рассылки и cookies остаётся доступен.
7. Заполнить налоговые настройки с бухгалтером. Для внешнего платежа выключенный `YOOKASSA_RECEIPT_ENABLED` теперь блокирует создание платежа. Подтверждение заказа не является чеком.
8. В админке заполнить сведения по товарам, проверить область действия и актуальность документов, права на каждое фото / принт и маркировку. Объект JSON в карточке и отметка «проверено» не являются сертификатом или лицензией.
9. Выполнить проверку готовности. По умолчанию она проверяет только конфигурацию; `--products` дополнительно делает явно запрошенное чтение настроенной базы:

```sh
npm run legal:check
npm run legal:check -- --products
```

До заполнения фактов код возврата проверки — 1. Это ожидаемое указание на незакрытые требования, а не повод поставить фиктивные отметки.

## Фискальные сценарии, которые ещё требуют подключения

Текущая интеграция создаёт чек вместе с обычным внешним платежом, но не обеспечивает все операции с авансами, зачётом баланса и кодами маркировки. Поэтому реальные платежи за подарочные сертификаты и маркируемые товары заблокированы до подходящей интеграции, а использование баланса в production остановлено до правильного оформления зачёта аванса. Остатки и ранее выданные сертификаты сохранены. Их денежный возврат по требованию должен обработать продавец.

Выбрать фактически используемую кассу и её сценарий. Реализовать и проверить на ней продажу сертификата как аванса, частичное использование, полный зачёт, возврат оплаченного остатка, обычную предоплату / передачу товара и возврат, а также реквизиты маркировки. Для обычного заказа при передаче товара обеспечить чек зачёта предоплаты, если он требуется в конкретном случае. Проверять фактическую регистрацию и получение чека покупателем. Тест с имитацией оплаты не доказывает регистрацию в ККТ.

В [документации «Чеки от ЮKassa»](https://yookassa.ru/developers/payment-acceptance/receipts/54fz/yoomoney/parameters-values) аванс и частичная предоплата этим решением не поддерживаются. Не включать сертификаты простым подставлением `advance` в неподходящий сервис. [Правила формирования чека при платеже](https://yookassa.ru/developers/payment-acceptance/receipts/54fz/yoomoney/payments) требуют совпадения суммы чека и платежа; смешанная оплата текущему коду не соответствует.

## Действия продавца после публикации

- Для каждого отправленного заказа вкладывать письменные правила возврата с действительными адресом и получателем. Возможность скачать правила на сайте не заменяет предоставление информации при доставке. Можно использовать сохранённый документ заказа как источник памятки.
- Претензии принимать по указанной электронной почте. Фиксировать дату требования; срок возврата денег нельзя запускать заново после проверки вещи. Возврат почтой / перевозчиком не запрещать.
- На время спора включать отметку сохранения документов в заказе. Для связанной записи `ConsentRecord` поставить `legalHold=true` до разрешения спора; затем пересчитать срок хранения с учётом применимых требований.
- Перед каждой ручной рекламной рассылкой получать свежую выгрузку, сопоставлять её с собственным сервисом отправки и включать персональную ссылку отказа в каждое письмо. Не использовать старые CSV после отзыва. Отказы по почте обрабатывать немедленно. Двойное подтверждение адреса по email желательно подключить с выбранным российским сервисом отправки; автоматическая отправка и подтверждение владения адресом в текущем проекте отсутствуют.
- Удаление аккаунта и запросы субъекта обрабатывать через поддержку с проверкой личности соразмерным способом. Не удалять документы расчётов, которые ещё требуется хранить по закону. Данные необязательного профиля удаляются при отзыве в интерфейсе; старые необязательные поля без подтверждения очищаются обработкой сроков.
- Проверять рекламные кампании отдельно: когда требуется маркировка рекламы / ERID, оформлять её через соответствующих участников. Обычная карточка собственного товара не означает автоматическую обязанность маркировать каждый элемент сайта как рекламу.
- Утвердить внутренние документы по персональным данным, полномочия сотрудников и договоры с обработчиками; организовать обработку запросов и реагирование на инциденты, включая предусмотренные законом уведомления. Публичная политика не заменяет эти меры.

## Обработка сроков хранения

Команда предназначена только для выбранной и проверенной базы. По умолчанию она **ничего не удаляет** и показывает количество затрагиваемых записей:

```sh
npm run data:retention
```

После проверки настроек и полномочий запланировать на российском сервере ежедневное выполнение:

```sh
npm run data:retention -- --execute
```

Удаляются аналитические события старше 180 дней, просроченные сессии / гостевые корзины, необязательные поля профиля без согласия, отозванные адреса рассылки через 30 дней и доказательства отзыва через три года без отметки спора. Согласия рассылки старше трёх лет и старые подписки без доказательств отключаются. Согласия аналитики закрываются через 180 дней; для старых отказов от рассылки без даты запускается 30-дневный срок удаления. Отдельно удаляются неоплаченные незавершённые заказы старше года без списания баланса, уменьшения склада и отметки спора. Оплаченные заказы этим заданием не уничтожаются: их обязательный срок и последующее уничтожение нужно организовать отдельно по фактическим документам и законодательству. Требования субъектов со специальными сроками обрабатываются отдельно, а не ждут задания.

## Результат локальной проверки

- Сборка, проверка типов и проверка кода завершились успешно.
- Пройдены 6 проверок правил и 8 интеграционных сценариев на отдельной временной PostgreSQL, включая отказ / отзыв согласий, сохранение документов заказа и сроки хранения.
- В браузере видны все 55 действующих товаров из каталога проекта; исходные фото и GIF загружаются. На ширине 390 и 1440 пикселей проверены согласия и форма подписки; горизонтального выхода за экран нет. Отказ от аналитики и повторное открытие настроек работают.
- `legal:check` ожидаемо сообщает о восьми незаполненных / неподтверждённых настройках. Это **не** успешно пройденная проверка готовности к выпуску.
- Код публичного сайта не обновлялся; в подключённой базе применены только добавления к схеме после резервной копии. Вход и чтение сессии проверены; реальные платежи и рассылки не выполнялись.

## Проверки перед переключением трафика

```sh
npm run db:migrate:deploy
npm run db:generate
npm run typecheck
npm run lint
npm run test:legal
npm run test:legal:integration
npm run build
```

Интеграционная проверка создаёт отдельный временный PostgreSQL и отдельный экземпляр сайта; рабочая база и реальные платежи не используются. Требуется установленный PostgreSQL. После выпуска отдельно проверить публичные формы, отказ от аналитики / рекламы, сохранение документов, реальный чек и реальные настройки инфраструктуры.

Правовая основа и исходные наблюдения: [аудит от 05.10.2026](../velocityclub-legal-audit-2026-10-05.md). Изменения не являются гарантией отсутствия штрафов: неизвестные факты, обязанности вне сайта и работа фактической инфраструктуры остаются условиями соответствия.
