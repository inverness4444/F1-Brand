# Исправление оформления заказа — 5 октября 2026

Причина: при `CATALOG_SOURCE=file` публичный каталог содержал 55 товаров, но восемь товаров Teddy Bear отсутствовали в PostgreSQL. Сохранение корзины пропускало неизвестные варианты, возвращало успешный ответ и оставляло серверную корзину пустой. Оформление затем возвращало общее сообщение «Переданы некорректные данные» до обращения к ЮKassa.

## Рабочая база

- Создана и проверена полная резервная копия: `/Users/abuzada/.codex/backups/velocityclub/2026-10-05T11-48-38-327Z/before-catalog-sync.dump`.
- Импортированы только восемь недостающих товаров с текущими ID, ценами, изображениями, размерами и расцветками. Существующие товары не перезаписывались.
- Количество товаров изменилось с 72 на 80; аккаунтов осталось 4, заказов и платежей — 0.
- Сверка всех 55 публичных товаров: недостающих вариантов для оформления больше нет.
- На публичном сайте проверено сохранение белой футболки XS в корзине. После проверки восстановлено исходное количество 1; сумма — 3890 ₽.
- Проверка доступа к настроенному API ЮKassa прошла успешно (запрос списка платежей, без создания оплаты).

## Изменения проекта

- При наличии PostgreSQL сохранение каталога записывает товары и варианты в базу заказов также в файловом режиме. Удаление товара отключает его варианты в базе.
- Запись одного товара и его вариантов выполняется в транзакции.
- Корзина отклоняет отсутствующие варианты и недостаточные остатки с понятной ошибкой; прежняя корзина сохраняется.
- Оба маршрута оформления явно сообщают о пустой серверной корзине.
- `npm run catalog:sync` показывает отсутствующие товары. Вариант `-- --apply` сначала создаёт и проверяет резервную копию, затем добавляет отсутствующие товары.

## Проверка

6 проверок правил, 10 интеграционных сценариев в изолированной PostgreSQL, проверка типов, линтер и производственная сборка прошли. В интеграционном сценарии файловый товар White/XS оформляется на 3890 ₽; запрос чека содержит товар на 3500 ₽ и доставку на 390 ₽. Настоящие заказы и списания для проверки не создавались.

Исправление данных уже применено к рабочей базе. Изменения исходного кода находятся в рабочем проекте и ещё не опубликованы; следующие сохранения каталога на старой опубликованной версии могут снова расходиться с базой. Перед публикацией общей версии также нужно закончить настройку реквизитов и инфраструктуры по отдельному юридическому чеклисту.

## Локальная кнопка оформления

Проверка отсутствующего срока доставки ошибочно отключала кнопку также в `next dev`. Клиент и сервер теперь используют одинаковое правило: в режиме разработки оформление допускается с пустым сроком, в production для физического товара требуется заполненный срок. Дата не подставляется автоматически, выбор платёжного провайдера сохранён.

Проверено на открытом `localhost:3000/checkout`: кнопка активна, два исходных товара и сумма 7000 ₽ сохранены. 7 проверок правил и 11 интеграционных сценариев без настроенных сроков прошли; типы и линтер также проверены. Интеграционные заказы созданы только в изолированной базе с mock-оплатой.
